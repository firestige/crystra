# 活动图：分层拼装与路线选择优先候选

状态：2026-09-11 用户确认作为**当前最优先候选**，用于工作流工作台 v8 的下一轮评审。不是全场景最终验收，也不是已发布的执行 JSONIR 契约。本文记录本轮完整显示效果依赖的规则，包含此前逐步形成的约束，不仅是最后增加的端口与标题修补。

## 权威与替代关系

本说明优先于 [引擎评审记录](workflow-map-engine-review.md) 中旧的布局实现细节。旧记录中的职责、Chat 协作、草稿与发布门禁继续有效；旧的 INCLUDE_CHILDREN 整图布局、按视口节点数动态算间距、按相对位置一次决定连接面、渲染时才绘制外置标题，不再代表当前 v8 样本的布局方案。原记录保留历史，不得把两套算法混合宣称为当前实现。

[横向暂可用标记](../assets/experiments/route-choice/CHECKPOINTS.md) 保留上轮快照；当前候选在其上加入同面端口搜索和纵向标题避让。横向节点几何保持该快照一致，返回线可因更优候选变化。新场景仍需验证，不允许通过写业务节点坐标来维持既有样例。

## 1. 工作台与语义输入

活动图是工作台的核心，Chat 用于表达意图、提出问题与修改。用户面对活动、判断、并行、成果和资源，不必理解 Action 或 Delivery 的运行实现。引擎负责几何与路由，Agent 负责将意图整理为语义输入；不能让 Agent 输出像素、端口位置或折线路径。

- `parent` 表示问题分解层次；复合活动折叠为一个活动，展开为自己的子流程，不把全部分支提升到顶层。
- 顶层仍保留属于顶层的决策，例如阶段完成后的整体验证与返工去向。内部决策留在内部，不能因分层丢掉控制流，也不能为了展示控制流把所有层级展开。
- 连线保留 `id/from/to` 真实身份。折叠只改变投影，`summaryLabel` 可描述阶段结果，不能改写原条件。
- `intent` 区分 expected/rework/recovery/exit；`layoutRole` 区分 advance/return。返回关系在执行方向上仍指回目标，但不能反过来支配预期路径的主轴排序。两者不是同一个字段：保障分支进入补救活动也可以是 advance。
- `layoutRole` 是当前候选 authoring 扩展，必须来自用户意图确认，不按标题或 ID 猜测。省略仍可读取旧定义，但不能声称具有同等布局信息。它不是 Execution System 的最终字段。
- 草稿允许不完整；发布版本才是执行准入门禁。结构检查可发现明显错误，不能保证运行无错。运行契约、资源解析、权限和版本发布由相应系统负责。

## 2. 自底向上的拼装

每个真实容器分别交给 ELK 做平面布局，使用 SEPARATE_CHILDREN；已展开子图先完成内部布局，以宽高和接口作为父图的构件。父级移动构件时整体平移内部节点、连线、标签和边界，不重新打散内部构图。折叠容器仍保留接口语义。

每条跨容器连线在经过的容器边界建立独立接口：身份由容器和原始边身份组成，保存 in/out、侧面、内部目标和外部来源。横向主推进默认左进右出，纵向上进下出；返回和退出可用侧轴。已选侧面贯穿折叠与展开，不能展开后把顶部接口任意绕到左侧。容器四侧不是业务含义固定的禁区。

开始节点使用 FIRST_SEPARATE，结束使用 LAST_SEPARATE，避免被普通活动包在图内部。返工边参与主轴排序时采用逆向的布局依赖，输出时恢复真实箭头方向；绝不改变执行语义。

### 透明补救分组

仅在以下结构成立时，将判断与其补救活动放入垂直于主轴的透明局部构件：判断通过 recovery/rework 的 advance 边指向同父级活动；该活动不属于 expected 主干；只有一个进入和一个 return 出口；返回目标在同一真实父级；没有重复占用或身份冲突。

横向主流程中该构件纵向排列，纵向则横排；判断留在主干，补救活动位于侧方。透明构件不出现在 UI 大纲或语义层级，不创造新的用户活动。条件不成立时不强行套用。它解释了“澄清缺口靠近材料判断”，不是针对开发场景的特例。

构件的预期接口对齐判断主轴；补救返回接口对齐处理活动；局部再次由 ELK 和 libavoid 处理接缝。去掉透明边界后，同一关系仍保留完整路线与真实边身份，重复条件标签只保留一次。真实容器边界不能跟着被删掉。

## 3. ELK 配置与几何资产

当前实验单位为 CSS px，尺寸是候选几何政策，不能和主题色混用。来源为 `elk-refinement/puzzle-candidate.cjs`；新增主题不得任意改变安全距离。

| 配置 | 当前值 / 目的 |
| --- | --- |
| 算法 / 路由 | layered / ORTHOGONAL，禁止贝塞尔替代 |
| 层级 / 合线 | SEPARATE_CHILDREN；mergeEdges=false，避免多条关系挤成单端口 |
| 普通节点间距 / 层间距 | 36 / 40 |
| 边到节点 / 跨层边到节点 | 28 / 28 |
| 边到边 / 跨层边到边 | 20 / 20 |
| 端口间距 | 24，沿轮廓分布并避开角点 |
| 容器 padding | 上64、左56、下56、右56；透明构件四边12 |
| seed / cycle breaking | 17 / GREEDY，稳定输入与确定性候选顺序 |
| 活动 | 宽 max(160, 字符数×16+40)，高88，圆角12 |
| 判断 | 同宽规则，高136，菱形；端口贴合菱形轮廓 |
| 开始 / 结束 | 48×48，端口贴合圆轮廓 |
| fork / join | 横向14×96，纵向120×14 |
| 展开容器 | 圆角14；尺寸由内部图产生 |
| 边条件标签 | 每行最多7字符，宽 min(98,字符数×14)+12，高 行数×20+8 |

端口先按稳定身份排序，必要时评价同侧反序；不是最大限度共享连接点。矩形、菱形和圆形分别贴合轮廓，不能使用包围盒角点冒充轮廓端口。普通活动可用 FIXED_SIDE；容器、判断、起止或已选择端口顺序的对象用 FIXED_POS。

全展开种子搜索比较：返回/退出的两侧轴选择、相关节点各侧端口顺序、局部 NETWORK_SIMPLEX/LINEAR_SEGMENTS/SIMPLE 布置策略。按穿节点、标签碰撞、交叉、净空缺额、重叠、段数、长度依次比较；最多7轮，拒绝失败候选。配置再复用于展开状态。保存的 search.config 是搜索结果，不是人工业务规则。

当前构件种子仍受早期 WEST→SOUTH（横向）/NORTH→EAST（纵向）返回假设影响；后续路线选择会替换返回路径，但不会消除这种种子影响。不得声称节点和路线已达全局联合最优。

## 4. 固定几何上的路线选择

节点、真实接口、容器、其他边先冻结，再对同一真实作用域中的无标签返回线选择出口。每条线枚举源4面×目标4面；最多两条联合枚举256种面组合。候选由 libavoid 原生正交路由，应用代码负责约束与评分，不自写像素折线。

同面候选包含中心、±24/±48偏移、对端中心投影、障碍物28px安全边界投影；离角至少16px，同面已有端口20px范围内不可复用。窄条相反两侧不视为同面冲突。原生同类 ShapeConnectionPin 提供多个候选，允许引擎选位置。

每个面组合保留原单端口模式与多端口模式竞争：一条线2种模式，两条线4种模式。原生端口连接代价是偏移×1.1；不因原生目标和外部目标不一致而直接丢弃旧候选。这不是连续端口位置的穷举。

硬约束：端点合法、正交、不穿节点/文字、不离开真实作用域、箭头前直段≥24px。障碍安全缓冲28px。无可行候选明确失败，不偷偷移动节点、缩小安全距离或沿用失效图。

| 外部候选代价 | 权重 |
| --- | --- |
| 严格交叉次数 | 100000 |
| 共线重叠长度 | 10000 |
| 与其他线小于12px的间隔缺额积分 | 100 |
| 拐弯次数 | 80 |
| 曼哈顿长度 | 1 |
| 端口距面中点偏移 | 1.1 |

libavoid 原生参数另为 segmentPenalty=80、crossingPenalty=200、fixedSharedPathPenalty=200、idealNudgingDistance=12、shapeBufferDistance=28。它与上述外部候选评价不是同一个函数。同分按稳定枚举顺序选取，尚无交互编辑稳定性代价。

只在真正的语义终点（或折叠后承接该目标的可见活动）绘制箭头；透明接缝不能每段都加箭头。真实容器接口另以圆点呈现，聚焦时显示“来自/前往”以及外部活动名，可查看真实关系、内部接入位置及外部去向。缩略图仍保留全局结构。

## 5. 文字、颜色与图形

纵向 fork/join 标题必须作为外置文字框进入 ELK，再进入路由障碍集合；位置为 OUTSIDE V_CENTER H_LEFT。当前用 Chrome 测量17px system-ui文字，横向额外8px，高26px、baseline19px。渲染使用布局输出坐标，不靠背景遮住压线。已测标题见 caption-metrics.json；新文本与字体应重新测量，未知文本的保守估算不能替代验收。

活动为圆角矩形、复合活动仍是活动但有单一 chevron 展开提示、判断为菱形、fork/join 为实心条、开始为圆形、正常完成为终点环、终止为圆内叉。不额外加重复的“+”。

沿用 [workflow-map.tokens.json](../assets/workflow-map.tokens.json) 的语义色；配合共享 card 的灰度表面、低对比边框、圆角和阴影。活动青绿、复合蓝、判断琥珀、并行控制紫；这些是类型色，不是运行状态。

连线 expected 青绿实线、rework 琥珀长虚线、recovery 紫色点划线、exit 红色短虚线、material 蓝色虚线、未分类灰色；箭头和接口跟随关系颜色。选中用线宽/透明度强调，不覆盖原语义。颜色不能代替形状、条件文本或 tooltip。布局数值政策与主题 token 分别管理。

## 6. 镜头与交互

可见区域是镜头，完整图是世界。优先用合理紧凑布局提高文字可读性，再取景；不为了“同屏”无限压缩节点，也不把整图最远缩放当成唯一适应视图。

- 展开活动：打开其祖先与自身，以展开后的容器居中并平滑取景；隔离非关注层内容，保留接口来源。进入另一个活动必须更新焦点。
- 返回上层：以父层重新取景；收起聚焦活动后回到父层。记住焦点和展开集合，用户拖动后“返回焦点”能恢复。
- 适应当前层和全图概览分开；手动平移、滚轮和缩略图移动解除视觉隔离但保留焦点记忆。
- 大纲仅列可展开复合活动，用于快速导航，不堆叶子节点；大纲收起/展开有动画。缩略图提供全局移动与视窗定位。
- 选中节点可强调结构上能到达它的上游路径，淡化无关内容；这是结构可达性，不是宣称条件一定满足。预期路径模式与全部路径模式分开，保障路径减淡但仍可辨认。
- 工具放在 header 右侧；icon button 有 tooltip 和可访问名称；路径和方向菜单向上展开。点击节点/接口的详情与 Chat 引用保留。
- v8 沿用共享 camera 的取景、动画与焦点恢复逻辑；接口文字也应计入焦点取景留白，避免标签在容器外被裁切。

## 2026-09-13：结晶图接入与前向汇合补全

结晶图此前误用旧通用引擎，现改为复用本候选的 branch-block/puzzle-candidate 与 route-choice。新 fixture 的种子无质量缺陷，无需种子配置搜索；路线依旧枚举端口并评价。旧56状态不重写。布局资产与输入完整匹配，不匹配拒绝展示，不静默退回旧引擎。

透明补救构件除原 return 模式，新增受限的前向汇合模式：触发者为 decision，保障 advance 边到同父级的非 expected 主干 activity，辅助活动恰有一进一出；其 advance 出口指向触发判断的直接 expected 后继。其余身份、同层与不重复占用条件沿用。局部横向图仍把判断与辅助活动沿纵向拼装，辅助出口从下方汇入主干后继；纵向按侧轴转置。这里没有 return 执行关系，不反转布局依赖，不改原始边语义。

新条件不成立时保持常规布局。它保证辅助活动在主干侧方，不保证位于某个后继的严格正下方；具体横坐标和端口由引擎与代价选择。`workflow-crystallization-layout.test.cjs` 验证改名、横纵方向、输入不变、零交叉/穿节点/标签碰撞和 advance 保留。生成审计见 `assets/workflow-crystallization-layout-audit.json`。现有 branch/route/v8 共13项回归通过；不外推到任意多分支或跨容器结构。
