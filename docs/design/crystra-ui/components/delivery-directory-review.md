# Delivery 检索目录（已确认）

2026-09-10 用户确认。本文为字段检索、当前结果筛选及目录布局的正式设计契约（D20）。样本位于 [组件样本](../assets/component-preview.html)顶部；Analysis v8 已接入共享 DeliveryDirectory。

## 数据单位

每行代表一个 Delivery，并携带精确 traceId。Task 是可接续的业务上下文；Task／Workflow 的名称和身份用于查找及消歧，不把相同 Task 的 Delivery 合并成一条 Trace。

Header 时间范围约束检索。当前设计按 Delivery 开始时间命中，按开始时间倒序，Delivery ID 作为相同时间的稳定次序；首批 10 条，向下滚动继续追加，无分组、无页码。生产事实及 terminal 语义仍由 docs/ 和记录提供，不根据某个 Span 是否结束来推断。

## 1. 字段检索：明确索引能力

检索字段由调用方提供的索引能力清单决定。组件只展示清单中声明的字段，不把所有记录属性拼接成全文搜索，也不从名称推断后台是否有索引。

当前 UI 样本使用候选清单，不代表后端已经具备相应索引：

| 字段 | 匹配规则 |
|---|---|
| Task ID | 完整 ID 精确匹配 |
| Task 名称 | 名称关键字查找 |
| Workflow | 无 `@` 按名称关键字检索；有 `@` 按唯一 selector（name@version）精确匹配 |
| Delivery ID | 完整 ID 精确匹配 |

字段下拉选择器嵌入 SearchField 的 prefix，采用 ghost 外观：默认、悬停、聚焦及展开时均无独立背景、描边或阴影，与输入共用一个表面和焦点态，不单独占一行。选项不展示“精确／包含”或操作符。选择字段后输入值，Enter 执行当前字段检索，替换上一次检索。输入中的草稿不立即改变结果；输入法组词中的 Enter 不提交。清空输入后按 Enter 取消字段检索，恢复 Header 时间范围内的结果。缺少索引能力的字段不可查询，也不可退回任意字段的隐式全文匹配。

搜索框不提供加号，也不生成检索条件 chip。Chip 仅表示结果筛选条件，逐项关闭不会清空当前检索。

### 正式检索交互契约（2026-09-10 用户确认）

以下是正式实现必须遵守的规则，不以 HTML 的本地数组演示或当前后端能力替代：

- ID 字段默认精确匹配完整身份，不允许前缀或包含匹配；名称字段默认按关键字查找。界面不要求用户选择匹配操作符。
- Workflow 使用一个检索字段：输入不含 `@` 时对 Workflow 名称做关键字查找；含 `@` 时将整个输入作为唯一 selector 精确匹配，不再进行名称关键字查找。
- 例如 `Implementation` 或 `imple` 为名称关键字；`Implementation@v3` 只命中该 selector。`Implementation@` 或不存在的 selector 不得降级为名称搜索、忽略版本或自动选择最新版本。
- 字段选择器位于 SearchField 的 prefix，字段名称、placeholder、可检索清单由页面／查询适配器传入；共享控件负责布局、焦点及键盘行为，不决定业务匹配语义。
- 每次 Enter 提交当前字段及输入值，替换上一次检索，不累加检索条件，不生成 chip。结果筛选在当前检索结果上继续约束，不能隐式改写检索。

HTML 仅演示字段选择、检索提交和筛选删除、表单展开及选中反馈。真实索引覆盖、名称关键字分析器（分词及大小写）、selector 的权威解析与唯一性、查询快照和游标需由正式查询接口保证；本地样本的字符串包含判断不构成后台检索实现。上述接口未提供时应明确能力不可用，不得自行扩展隐式全文搜索。ID／selector 按系统身份规则原样解析，不由 UI 擅自大小写归一化。

### Prefix 与结果区布局

Prefix 的 ghost 字段选择器使用细线 chevron 替换实心三角，展开旋转 180°，220ms 过渡，reduced motion 取消动画。

SearchField 的 prefix slot 按注入内容撑开，仅设最大宽度为搜索框内容区的 45%，避免挤占输入区；共享控件不规定注入元素的固定宽度。Delivery 目录自身将下拉选择器设为 96px，切换字段不移动输入区；与输入区之间使用 16px 高的灰色细 divider，上下留白，不贯穿搜索框。结果区 chip 整体与右侧命中数量垂直居中，chip 换行后仍以整个 chip 区域居中对齐。

Prefix 字段文字靠左，chevron 固定靠右（靠近 divider），不随文字长度移动。搜索框无加号；Enter 执行当前检索，chip 仅用于结果筛选。


## 2. 当前结果筛选：向下展开的表单

搜索框下方使用中间由细线 chevron 隔断的灰色 divider 作为展开入口，无按钮底色和可见文字。保留按钮语义、可访问名称「筛选当前结果」、键盘操作和 aria-expanded。展开时表单从搜索框下方向下出现，将 divider 向下推；收起时同步复原。divider 下方、列表上方的一行左侧放结果筛选条件 chip（可换行），右侧放筛选后命中数。

表单只接收本次字段检索已经得到的结果集合，提供结果中的 Task、Workflow、版本选择。选项显示名称 + ID，实际用 ID 消歧；版本也从当前检索结果提取。它不启动新一轮全库字段检索。

筛选条件彼此独立，修改或删除 Task 筛选不连带清除 Workflow 或版本。不兼容组合明确返回零条。收起表单保留条件；活动筛选以独立 Chip 显示，逐条可关闭。没有“一次全清空”作为唯一管理方式。

命中数量是当前筛选后集合的数量，表单注明本次字段检索得到的基础数量。样本在完整本次结果集上筛选，然后切出无限滚动窗口，避免前 10 条没有匹配就误报零条。生产实现应明确本次查询快照及完整结果集合的处理方式，不得把仅加载的可视页冒充完整结果。

## 3. 选择与显示范围

初始有结果时选第一条。条件或时间变化后，当前 Delivery 若仍命中则保留，否则选择新的第一条；零命中输出 null，清空右侧旧 Trace。追加结果和切换瀑布图／树图不改变选择。

选择 Delivery 不隐式改写 Header 的 Task 范围。精确深链定位失败不能静默回退到另一个 Delivery。开始时间命中与时间区间相交属于不同策略，当前样本采用前者，生产端跨范围长调用策略仍需数据契约明确，不影响本次视觉及交互设计确认。

## 组件复用

- SearchField：字段值输入，页面提供 label、placeholder、前缀和 Enter 检索处理。
- SelectField：`appearance="embedded"` + `hideLabel` 嵌入搜索 prefix；默认形式用于结果筛选表单。前缀保留键盘操作及可访问名称。
- Chip + IconButton：逐项删除结果筛选条件，不自绘第二套 Chip。
- List / ListItem：Delivery 扁平结果；已确认 `selectionAppearance="surface"` 使用灰度选中态，无行描边。
- 灰色 divider + chevron：展开／收起表单；220ms 过渡，reduced motion 下取消过渡，收起表单 inert，条件仍保留。

## 验收要点

- 切换字段时，下拉选择器保持页面指定宽度、chevron 靠右，输入区不来回移动；其他页面注入更小内容时 slot 随内容收缩，超出上限时不能挤没输入区。
- Prefix 无独立背景或描边，16px 分隔线不贯穿搜索框；默认、悬停、聚焦和下拉展开均维持 ghost 表面。
- Enter 执行单次字段检索，空输入提交恢复时间范围内结果；无加号，不生成检索 chip。
- 筛选表单从搜索框下方展开，灰色 divider 随表单下移；收起保留筛选。所有筛选 chip 位于 divider 下方、列表上方的左侧，命中数靠右，与整个 chip 区域垂直居中。
- 删除一个筛选 chip 不删除其他筛选或改变当前检索；数量反映完整当前结果的筛选后总数，不是已加载行数。
- 列表扁平、无分组、无页码，默认选中最新 Delivery；追加不改变选择，零结果清空右侧 Trace。
