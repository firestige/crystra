# 审核卡与完整查看

> 继承 U1「卡片设计原则」「执行摘要」「Delivery」；系统指标意义由 S3/S6/Catalog 拥有。

## 审核卡结构

每张卡回答一个可独立扫描的问题：标题 → 当前结论/影响 → 最小支撑事实 → 只读详情入口。普通健康项合并，异常展开。仅当需要独立比较或强调时拆卡；不把 schema 每个字段变成一张卡。

| 变体 | 使用时机 | 内容边界 |
|---|---|---|
| Summary | 正常项压缩 | 计数、结论、来源/范围；不伪造质量总分 |
| Attention | 缺口、冲突、风险影响判断 | 具体问题、控制影响、精确 Gate/证据入口 |
| Delta | 当前 revision 相对上次有效版本 | 新增/删除/冲突；不丢弃未解决争议 |
| Readiness | 准备度/可交付判断 | 适用范围、时间、来源；不推导自动完成 |
| Evidence entry | 支撑当前判断的材料 | 角色、关系摘要、精确身份与去向；不只有文件名 |

默认只读。卡片内部可以有浏览入口；“批准/拒绝/重排/执行”回 Input，不通过卡片点击直接写业务状态。

## 卡片尺寸、空数据与完整查看（用户已确认，D05）

适用于 control-bench 内的卡片。这里的 control-bench 指右侧当前工作面的可用内容区域；扣除实际 Header、工作面导航和已打开的文件工具面等占用，不使用整个浏览器高度替代。该名称表示布局区域，不新增系统身份或强制改名现有 DOM。

1. **卡片设置最小高度。** 空数据与有数据时保留稳定容器；已接受的页面主卡/空卡基线见 [空间变量](../foundations/spacing-and-shape.md#应用边界)，嵌套说明 Surface 不机械套用主卡最小高度。实际高度必须同时受当前工作面可用高度约束；首期按 1920×1080 及以上目标屏幕的正常使用场景设计，极小窗口适配后置。
2. **缺乏数据时允许空卡片（D06 补充）。** 显示对应的“No xx”/“没有待裁决内容”，或使用静态骨架、半透明空文件图标；不强制同时展示文字与图标，纯图标需有可访问名称。普通本地数据空态不显示“加载中”。确有耗时读取时，由右下角悬浮通知小窗及进度条反馈，卡片不承担加载动画。不伪造数据、零值或进度百分比，读取失败或执行状态未知不等于确认无数据。
3. **单张卡片最高不超过整个 control-bench 的可用高度。** 卡片不得跨越多个可视高度，不能依赖滚动主工作区才能从一张卡的头看到尾。现有工作面是否仍有多卡集合滚动按页面布局处理，本条不等于禁止一切工作区滚动。
4. **大量内容在卡片内摘要化，超出部分省略。** 对纵向列表型卡片，在右上角提供展开入口，进入专用完整查看组件；该组件占满 control-bench，提供返回按钮和纵向滚动。展开是只读浏览，不新建 Session，不影响左侧 Input，不提交业务修改。

完整查看组件由固定标题/返回区和 `min-height: 0; overflow-y: auto` 的内容区组成；返回按钮不随长列表滚出。进入时保留来源卡片与 Gate/对象身份、revision 和浏览位置；正常返回恢复来源位置。若对象已变化或不可定位，按 [上下文查看的精确读取与返回规则](context-viewers.md#适用性读取失败与返回) 处理，不自动换成最新对象。

省略的是详情或列表后续项，不隐藏理解当前状态所必需的“已过期/不可访问”等提示。数据已有时显示真实摘要或历史标识，不因失去当前适用性就全部替换成空骨架。非纵向列表卡片同样受高度上限约束，其完整查看形态沿用对应 Plan/DAG/Inspector 契约，不凭本轮原则一律改成列表。

## Task Run 摘要（不是通用百分比组件）

`task-execution-summary` 组合 run-health、current-activity、execution-counts、attention-summary、latest-activity、run-consumption。完成与当前剩余按逻辑执行单元统计，剩余分运行/排队/阻塞三个互斥子集；循环历史 attempt 不重复计数，动态分支可使剩余增长。

局部 Workflow 节点进度、Wave 退出条件、Task 可交付性、Task Run 单元计数是四个不同口径。不得互相填空。系统没有提供合格 owner 数据时，用不可用状态，不从 DOM 或 Trace 噪声拼数。

## 状态与数据属性（设计层，非 API）

组件需要明确 subject identity、revision/读取范围、结论、完整性、来源引用和适用时点；可操作入口额外要求 kind 与精确目标。状态的可用/不可用不依赖图标颜色猜测。

普通 Task Summary 不因外形同为卡片而成为 BI 指标组件。已有指标组件的输入与适用边界见 [指标 API](library/metric-renderers.md)，事实状态和覆盖率展示见 [证据组件](library/evidence-status.md)；本页只维护审核卡的组织与完整查看规则。

## 可交付判断

不可交付 / 条件可交付 / 当前可交付只反映当前条件。Goal/约束/Replan 改变后旧判断失效、重新计算。验收 claim/verdict 的来源与风险是否已经裁决需可下钻；未知风险不得标记为已接受。累计成本和人的注意力必须有真实口径。
