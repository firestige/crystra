# 系统设计、科研管理专项复核

2026-09-11。复核使用当前自动出口版；没有为这两套样本补写连接面或坐标特例。

范围：系统设计的探索问题、形成架构方案、多角度评审；科研管理的收集与核对、计算与检查。横向与纵向、局部展开和全部展开均检查。

## 已验证

- 另外两套样本共 24 个导出状态都在真实浏览器中渲染，并核对可见语义节点数量。
- 18 张作用域/方向截图，检查各级进入、折叠与平移后恢复焦点。页面没有运行错误。
- 这两套样本共 16 次局部出口评估、256 个候选；所有选中返回线均为本轮候选中的最低代价，没有新增严格交叉或共线重叠。
- 系统设计的“调整方案 → 比较架构方案”，以及科研管理的“请求补充材料 → 收集两类材料”“核实并修正记录 → 计算进展指标”，均自动选择出口。横向为 WEST → SOUTH，纵向为 NORTH → EAST。
- 横向沿用已标记节点几何；纵向因文字包围盒重新进行 ELK 布局。返回路由阶段仍冻结各自布局种子的节点与其他连线，不能将其所有视觉质量归功于出口选择。

## 原复核发现与本轮处理

1. 科研管理纵向“收集与核对”：返回线在 x=524 → 536 处有一个 12px 台阶。“读取关键动作记录”右边界 x=508，加 28px 安全间距后，路线需要到 x=536。这不是无障碍区域的随意绕行，但如果同一面的端口位置也参与搜索，可能进一步简化。原轮只有连接面搜索。本轮已增加同面候选端口；在原有冻结几何上回归验证，返回线由三次拐弯降为一次。当前纵向文字避让布局也保持一次拐弯。仍不是连续位置全局优化。
2. 同一视图里，“收集两类材料”等 fork/join 的外置标题与原主流程线靠得过近或重叠。当前这些标题由渲染器绘制，没有作为完整文字包围盒参与节点布局与路由避让。本轮已修复：纵向标题以真实测量包围盒参与 ELK 布局，放在横条左侧，并参与路由避让。浏览器逐状态核对实际 SVG 文字范围落在包围盒内，截图确认没有与连线重叠。
3. 全部展开时图会明显拉长，仍需要分层聚焦阅读。专项复核没有把全展开缩略状态当作正文阅读尺度的验收。
