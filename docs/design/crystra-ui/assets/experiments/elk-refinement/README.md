# 原 ELK 方案：侧向补救分支对照

2026-09-11。局部候选改进，供视觉评审；不是新的正式 JSONIR 或全局布局规范。

## 基线与范围

基线是 `../workflow-puzzle` 在两轮选库 spike 前最后一版：递归 ELK 构件、显式接口、推进/返回分类，以及已生成的端口搜索配置。`puzzle-baseline.cjs` 保存该引擎快照；对照数据读取该目录的 `layouts.json`。这比正式 v8 内的 15:57 版本更新。最初针对较早 v8 引擎做的端口排序诊断没有采用，记录留在 `legacy-diagnostic-results.json`。

本轮只处理一个问题：判断的单个补救活动被排到主路径的后续活动旁边，而不是靠近触发它的判断。没有替换工作台 UI、引入 BPMN 下钻样式，或修改正式 v8 / 设计契约。

## 候选机制

1. 从已有实验语义识别“判断 → 补救活动 → 返回前序活动”：进入边是 recovery/rework 的 advance，补救活动不属于 expected 主路径，仅有一个入口和一个 return 出口，相关活动属于同一真实作用域。
2. 为判断与补救活动生成透明的内部构件。ELK 沿主方向的垂直方向排列它们；没有根据名称或固定 ID 判断，也没有填入手工节点坐标。
3. 以第一次 ELK 结果中的节点位置约束构件接口，再交给 ELK 拼回父图。主路径接口与判断对齐，补救活动从朝向前序活动的一侧引出返回线，目标从补救分支一侧接入；各端点分别约束，不再强制双方使用同一连接面。
4. ELK 的侧向构件接口会产生多余折线，因此仅对这个内部构件使用既有 libavoid-js 做固定端点的正交路由。外部布局和路由继续使用原 ELK 引擎。节点与端口位置没有交给路由器改变。
5. 移除透明构件的展示节点与接口；保留真实节点、真实容器接口及原始边 ID。跨透明接缝的条件只显示一次。

未满足识别条件的多入口/多出口、共享处理流程等保持原方案，不能强行归入这套构件。既有 layoutRole 仍然只是实验假设。本轮继承基线已有的搜索配置，没有新增按样本 ID 编写的配置，也没有新增全局代价搜索器。

## 检查结果与实际限制

- 三套样本，横向/纵向共 56 个展开组合：原始节点和边覆盖、接口连接、正交性、节点互不重叠通过；严格交叉没有增加，测得共线重叠、非端点节点穿越、标签与节点碰撞为零。
- 五个测试通过，另含改名/加长标题、多入口反例，以及透明接缝主路径保持直线的检查。
- Chrome 完成 14 张前后对照截图，检查平移后的焦点恢复、折叠和第三层导航；没有页面运行错误。
- 开发样本的澄清缺口现在位于材料足够下方；系统设计的调整方案、科研管理的请求补充材料等按同一规则处理。
- 几何检查没有覆盖所有文字、外部接口说明和边之间的视觉关系，不能宣称整个活动图完成视觉验收。
- 补救返回线增加跨接缝的整体检查：无阻挡时只需一个拐弯；存在中间展开构件时，仍保留满足 28px 隔离间距所需的折线。部分状态的总路径长度可能略增。没有将这次改动描述为全局最优或所有问题已解决。
- 预览沿用原实验的导航、缩放和颜色；只增加“基线/改进”的对照开关。正式工作台的动画与完整交互仍需在决定采用后合入验证。

## 文件与复现

- `preview.html`：可直接打开；选择“理解与设计”后在顶部切换基线/改进。
- `branch-block.cjs`：结构识别与透明构件。
- `puzzle-candidate.cjs`：对原 ELK 拼装引擎的局部扩展。
- `local-router.cjs`：只负责透明构件内部的固定端点路由。
- `branch-results.json`、`branch-metrics.json`：全部状态的对照数据。
- `branch.test.cjs`、`verify-branch-browser.cjs`、`browser-check.json`：验证与结果。
- `candidate-0-plan.png`、`baseline-0-plan.png` 等：同一导航位置的真实浏览器截图。

在本目录运行：

```sh
node build-branch-preview.cjs
node --test branch.test.cjs
node verify-branch-browser.cjs
```

依赖沿用工作区 ELK 0.12.0 和第一轮实验中的 libavoid-js 0.5.0-beta.5（LGPL-2.1-or-later），没有写入产品依赖。预览是预计算几何；没有验证增量编辑性能或将 WASM 路由器接入正式 UI 的生命周期。

参考：[ELK 端口约束](https://eclipse.dev/elk/reference/options/org-eclipse-elk-portConstraints.html)、[libavoid-js 源码](https://github.com/Aksem/libavoid-js)。使用成熟引擎的能力，并不意味着本层语义适配无需维护。

## 返回线修正

原实现把补救出口固定为底部/右侧，并分两段路由，局部的拐弯惩罚无法比较从左侧/顶部直接返回的方案。本次按结构角色分别约束源、目标连接面：横向时 WEST → SOUTH，纵向时 NORTH → EAST。没有增加按名称特判，也没有宣称实现了全局斥力优化。新回归检查拼接后的完整返回线，并检查直达路径是否会侵犯中间构件的 28px 隔离间距；不能仅凭拐弯数量去掉必要的避障。`before-return-fix.json` 保存修改前数据。
