# Agent 指南：组件优先与新增设计审查

> 2026-09-10 用户明确规则。适用于创建、修改和验收 `crystra-*v8*.html` 及其共享组件；不表示现有页面已完成复用整改。

## v8 的交付标准

v8 系列 HTML 承担最终 UI/UX 的视觉与交互演示。不考虑业务接入时，已确认的页面应与最终产品在视觉和可演示交互上保持一致，不能以“只是原型”为由另做近似样式。HTML 无法覆盖的复杂交互，必须在对应页面文档中说明触发条件、状态变化、反馈、恢复方式及演示缺口。

组件样本是页面复用实现的审查入口。创建 v8 前已制作的语义化组件应尽可能复用；样本与页面应引用同一实现，而不是分别模仿相同外观。

## 工作流程

1. **先查现有能力。** 阅读[组件目录](../components/README.md)、[组件配方](../components/component-recipes.md)、[组件样本](../assets/component-preview.html)及其源码。确定已有组件和已审核变体能否直接使用或组合满足需求。
2. **能够复用就直接复用。** 页面负责数据、业务语义与布局组合，不另写一套基础控件外观和交互。已审核能力的正常复用不需要重复申请设计审批。
3. **能力不足时明确提出缺口。** 说明当前组件缺少什么、为什么现有属性或组合无法满足，以及拟增加的能力。不要静默退回原生元素加页面专属 CSS，也不要先在 v8 中落地新设计。
4. **先补组件和样本。** 在共享组件中增加候选能力，并在 `component-preview.html` 中展示可操作的候选样本，标注“待人工审查”。保留已审核默认行为；展示新增能力与原有形式的对照，以及受影响的默认、悬停、聚焦、输入后、禁用或展开／收起状态。审查范围按实际变更确定。
5. **请人工审查具体样本。** 提供样本位置、变更点及影响范围。明确认可前，暂停依赖该设计的页面接入；可继续不依赖该决定的工作。测试通过、文档写完或等待了一段时间都不等于设计获批。
6. **确认后再接入页面。** 记录获准的设计，更新组件契约，让相关 v8 页面复用该实现，删除被替代的局部实现与覆盖规则，重新构建导出样本和页面。
7. **验证一致性。** 同时检查组件样本和页面中的实际视觉与交互，尤其是全局样式叠加、焦点边界、圆角、尺寸及键盘行为；不能只验证功能可用或静态截图相似。

## 示例：SearchField 增加前缀图标

页面需要带放大镜的搜索框，而现有 SearchField 只有输入框和框外标签时，应先提出前缀能力缺口，在共享组件中添加候选前缀设计，再在组件样本中并排展示无前缀／带图标的状态，交由人工审查。明确整个控件的边框、焦点反馈、图标间距与输入区关系，避免容器高亮后内部 input 又出现一层方框。获准后才把该变体用于资源浏览器等 v8 页面。此例规定流程，不代表任何前缀 API 或聚焦视觉已获批准。

## 现状盘点与设计候选的区别

为快速分析问题，可以复制现有页面控件到样本页，固定差异并用于对照。这类内容应标注为“现状对照”，不能被视为已经批准的共享组件，也不能反过来成为 v8 的新实现来源。

当前搜索形式盘点属于现状对照。复制盘点本身不违反规则；需要纠正的是生成 v8 时绕开已有组件、遇到能力缺口未提出并补充组件的行为。

## 交付时提供的依据

- 页面使用了哪些共享组件，是否有新增或扩展能力。
- 新设计的样本位置、人工审查结论及待审范围。
- 样本与 v8 一致性的验证结果；无法演示的复杂交互对应文档位置。

不要把新增指南或已有页面通过构建，表述为所有历史复用问题已经修复。


## 当前 v8 的契约关联维护

四份已审核页面使用 [契约注册表](../assets/design-contracts.json) 与 [绑定索引](v8-contract-bindings.md)。共享动态组件按组件边界绑定，静态区域按稳定 ID 绑定，portal 内容须单独登记。新增动作即使位于已绑定区域，也必须先补对应文档的触发、状态和反馈；继承 owner 不等于自动批准新行为。构建后重跑静态清单、契约生成、运行态扫描、映射生成、`check-v8-parity.py` 与文档链接检查。没有绑定或文档文件不存在时不得交付；修改主题应验证实际计算样式，而非只检查变量声明。
