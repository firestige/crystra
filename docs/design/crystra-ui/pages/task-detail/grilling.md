# Grilling：问题全局与 Live Brief

> 继承 U1「Grilling 的特别要求 / 交互契约」；A1。页面壳见 [Task Detail](README.md)。

## 布局与内容

| section | 目的 | 数据与状态 |
|---|---|---|
| `grilling-overview` | 顶部进度概览 | 轮次、初始问题、已解决、待回答、条件问题、剩余主题、问题预算分别计数 |
| `grilling-question-map` | 问题域覆盖 | 原问题与新增问题区分；新增需来源与必要性 |
| `grilling-live-brief` | 当前仍有效的意图 | 目标、约束、明确排除、未解与缺失；不是聊天摘要 |
| `grilling-brief-changes` | 本轮相对前版的变化 | 新增/删除/冲突；AI 推测与用户确认分开 |

在右侧审核区按概览→问题地图→Brief→变化展开。卡片具体类值见 A1 与 DOM 索引，继承全局 panel、圆角和间距。

## 行为与状态

右侧无回答、删除、跳过、重排、确认退出按钮。用户回答、质疑和修订都在 Input。每项争论必须保留为已采纳、明确排除、仍有争议或尚未解决之一，不能整理时消失。

若增加来源定位入口，只能浏览到精确 source message，宿主能力未交付时不声称成功。尚无 Brief、部分问题未形成、读取失败采用明确空/加载/错误状态；具体文案为整理建议。

## 用户流程与验收

预期先看剩余问题与新增原因，再检查 Brief 是否误解，然后回 Input。验收：新增问题同步计数与来源；修改增量更新 Brief 和 delta；退出前可见缺失信息与预算；无第二写入口。参见 [用户流程](../../flows/task-work.md)、AC06。
