# 工作流工作台：业务接入需求

更新：2026-09-13。本文将本轮用户确认整理为后续业务逻辑的需求输入；不表示服务或包协议已经实现。页面交互见[流程设计](workflow-studio.md)与[资源配置](workflow-resources.md)，几何政策唯一入口为[布局优先候选](../components/workflow-map-layout-candidate.md)。

## 效力与职责

| 层次 | 负责内容 | 边界 |
| --- | --- | --- |
| 用户确认的 UI/UX | 层级阅读、直接绑定、资源管理、视图状态、内容呈现 | 本文与页面正文作为需求；不从旧样本恢复已否定设计 |
| workflow-package / 系统 owner | 包 envelope、资源用途与身份、执行定义、解析与发布校验 | UI 消费正式契约；缺能力提需求，不自建第二份权威索引 |
| Agent | 在当前 workflow workspace 理解意图、提出语义变更、维护底层资料 | 不生成坐标，不把未确认意图当作已应用配置 |
| 引擎 / Viewer | 校验、投影、布局、路线、镜头、选择 | 不更改控制流来改善图形，不自行生成执行语义 |
| 当前 v8 | 内存样本、候选 JSONIR、预生成布局与演示事件 | 不证明真实写入、通知、发布或任意图布局已完成 |

本轮允许直接编辑资源和直接修改活动绑定，替代早期 Workflow Studio“所有修改只能通过 Chat”的限制；Task 工作面的写入边界不因此改变。Chat 和直接编辑必须收敛到相同 workspace 校验与提交通路。

## UI 所需的语义数据

下表定义信息需求，不规定新 API 的字段名、文件布局或 wire schema。正式版本与适配方式由相应 owner 确定。

| 对象 | 必需信息与不变量 |
| --- | --- |
| Workspace 上下文 | 精确 workflow 身份、包位置、草稿/发布状态、revision；Agent 只操作该 workflow 包，外部引用不扩大写入范围 |
| 活动 | 稳定身份、显示名、包含层级、控制类型、输入输出、绑定引用、定义来源；名称不是身份 |
| 资源 | 稳定身份、类型、名称、用途、默认内容入口、载体归属、可编辑能力及版本；显示名与路径分离 |
| 绑定 | 活动身份、资源身份、绑定角色及来源；可解析到同一 workspace 的精确位置，不能靠同名匹配 |
| 关系 | 稳定关系身份、方向、语义类别、源/目标、声明来源及解析状态；调用、引用、成员归属、文档导航不能混为一类 |
| 内容快照 | 内容类型、读取版本、完整/截断/不可用状态、编辑基线；缺失不当空文件保存 |
| 诊断 | 稳定 code、严重度、文字说明、对象/关系身份、来源位置、修复入口；警告、阻塞、解析失败分开 |
| 变更提案 | 基线 revision、目标身份、操作与差异、校验结果、提交状态；陈旧提案不得覆盖新内容 |

Role、Skill 的索引项、入口文件与语义对象通过明确声明归一，不按文件名或显示名合并。归一不得产生 Implementer→Implementer 的伪自引用；真正跨资源依赖仍保留。资源分类在列表和活动绑定中同源：角色、技能、脚本／工具、模板、活动指令、参考资料。可见分类不等于每个活动都可以绑定每种资源。

### 活动绑定约束

叶子活动详情展示执行主体及关联资源；在活动上选择、替换、解除绑定，资源配置负责内容与对象管理。Role 与脚本执行方式互斥；Skill 只用于 Agent 活动且独立绑定于活动，不是 Role 的子资源；Template 可用于 Agent 或脚本。多文件工具的可调用入口仍由包契约确定，不从 README 猜命令。

切换执行方式时列出失效绑定和影响，不能静默删掉 Skill 或替换主体。选择器沿用资源类别与稳定身份，按适用性禁用不兼容项并说明原因。尚未配齐的草稿可保留诊断，发布前通过绑定与资源准入检查。节点展示应让用户发现绑定或缺口，完整信息进入详情；紧凑摘要的数量、溢出样式仍需组件评审，不能把旧 profile 卡片当定稿。

## JSONIR 输入要求

当前 authoring 候选是 `WorkflowMapIR version: "0.2"`，以[类型和 parser](../../../../wsr-ui/packages/bi/src/domain/workflow-map-ir.ts)为原型实现依据。它表达设计语义，不等同已发布执行 DSL。旧 0.1 多 Tab IR 仅作历史。

| 当前字段 | 解释 |
| --- | --- |
| version / title / description / nodes / edges | 候选版本、显示信息与实体集合；数组顺序仅作稳定阅读偏好 |
| node.id / kind / title / parent | 稳定身份；start/end/activity/decision/fork/join/group；parent 只能指向 group，禁止包含循环 |
| node.inputs / outputs / resources | 当前为字符串列表，尚不是 typed ports 或正式资源绑定协议 |
| node.join | all / any，仅用于 join；不能把普通多出边猜作并行 |
| node.outcome | completed / terminated，仅用于 end；正常结束与终止退出必须能区分 |
| edge.id / from / to | 原始关系身份与明确内部端点；不能以含糊 group 端点替代内部接入 |
| edge.kind | control / material；材料依赖不参与控制流可达性推断 |
| edge.label / summaryLabel | 条件说明与折叠摘要；摘要不改写真实条件 |
| edge.intent / trigger | expected/rework/recovery/exit 及保障触发说明；未分类不猜 happy path |
| edge.layoutRole | advance/return：语义上的推进或返回，由用户意图确认，不从名称/ID 推断；不是端口坐标 |

输入不得包含 x/y、尺寸、端口位置、SVG path、颜色或 CSS。层级、正常迭代、返工、恢复须经语义澄清；正常迭代可以属于 expected，保障活动的进入也可以是 advance。容器接口由真实跨层关系推导，保留来源、去向与内部接入点；展开/折叠不丢失输入输出，也不合并独立关系。

正式接入还需 owner 提供从 authoring 到执行定义的映射与来源追踪：输入输出类型、可执行条件/分支、调用与资源 selector、版本身份、子流程交接、重试耗尽和并行退出语义。不能把自然语言 label 当可执行 predicate，也不能从布局中的 group 推导新的 Runtime。上述是接入需求，尚无在本轮发布的新执行 schema。

### 校验、草稿和发布

1. 外部输入先做版本、结构、字段白名单、唯一身份、引用闭合、层级无环检查；失败保留最后有效图与错误位置。布局失败也不能把旧坐标套到新定义。
2. 可渲染但不完整的设计可以保存草稿。当前原型报告入口/结束缺失、空 group、不可达、无结束路径、终点后继、判断缺条件、并行/汇合不明、保障触发缺失等。
3. 原型的 expected 可达检查只证明到某个 end 的结构路径；生产需区分正常完成与终止出口，不能把终止可达当 happy path 完成证明。字符串资源列表不证明绑定正确。
4. 发布对准确 revision 重新校验执行映射、资源解析、绑定兼容、条件和接口、权限及包完整性；阻塞项未解决不得发布。草稿保存与发布是不同门禁，发布产物不可变。
5. 静态检查不能保证运行终止、条件完备或无运行错误；形式化程度与运行期保护由系统契约承接，不以 UI“检查通过”代替。

## 状态与变更协议要求

ViewerState（页面、资源、内容/关联图、展开集合、选择、焦点、相机、栏宽）与语义定义分离；浏览操作不生成业务变更。内容草稿按资源身份和基线保存；切资源不切导航，切页不丢 Chat。正式跨会话恢复由宿主接入，样本页内保持不等于持久化完成。

用户保存、增删改名、改绑定与 Agent 提案应用均需检查可写草稿、基线 revision、格式与引用，在一致性提交中更新内容和索引。检查到提交之间再次校验，失败保留输入，不留半个资源。外部修改或旧提案冲突不得静默覆盖；展示最新内容与草稿以供解决。

成功提交后产生系统资源/绑定变更事件：逻辑上包含 eventId、workspace、resourceId 或活动身份、operation、before/after revision、旧/新名称、影响引用；具体序列化由服务确定。提交与可靠待投递记录保持一致，按 revision 排序、eventId 幂等消费。Agent 收到后失效旧上下文并重新读取，不代表用户授权进一步修改。界面区分已提交、通知待发送、已投递和可重试失败；失败不谎报已通知。

“加入 Chat”仅插入精确对象引用到草稿并聚焦，不自动发送；与提交后的系统通知是两条不同通路。当前 v8 的 pending-runtime 事件和系统演示消息不能宣称已通知真实 LLM。
