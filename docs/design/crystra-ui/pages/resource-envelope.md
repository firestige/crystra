# 资源 Envelope：UI 消费要求与候选适配

更新：2026-09-13。**workflow-package 掌握 envelope 的决定权；资源配置只消费包语义。** 本页记录消费需求与现有原型，不发布字段 schema，不要求向已有闭合 schema 直接加入字段，也不建立 UI 独立资源权威。交互与提交要求见[资源配置](workflow-resources.md)和[业务接入需求](workflow-studio-contracts.md)。

## 对包契约的需求

用户操作 Role、Skill、工具、模板等对象，不操作索引与存储目录。包需让消费方可靠取得资源身份、类型、名称、默认内容、成员归属、引用和用途。具体字段、版本化、迁移和校验由包 owner 决定。

| 需求 | 可验收的消费结果 |
| --- | --- |
| 语义对象与稳定身份 | 索引、入口和成员可解析到一个资源；同名不合并，改名不破坏引用 |
| 类型和用途 | 列表与节点绑定分类一致；区分用户资源、维护资料、内部载体，不强迫用户学习目录 |
| 展示入口 | 多文件协作工具提供说明文档，单文件脚本可直接显示源文件 |
| 成员归属 | 工具脚本/库/测试不重复列项；Skill 附属内容按需展开；成员归属不冒充依赖 |
| 明确关系 | 区分允许调用、资源依赖、产出/材料、文档导航和成员归属；保留来源及解析状态 |
| 可写边界 | 按资源定位内容、版本与变更范围；已发布内容不可原地改写 |

[#269](https://github.com/firestige/workflow-self-recursive/issues/269) 已提出工具说明文档需求：多个文件协调工作的均算工具，不只 CLI。UI 先按 README 渲染，单脚本直接内容；包最终如何声明入口由 owner 决定。缺说明显示待补充，不能随便挑脚本冒充说明，也不执行文档里的命令。

[#270](https://github.com/firestige/workflow-self-recursive/issues/270) 已提出目录资源用途与消费边界：包括 agents/routes.md 的用途与可见性，不预定删除目录。UI 不因文件扩展名或文档链接推断业务参考资料。

## 当前非规范适配例子

[resource-presentation-v1.json](../assets/resource-presentation-v1.json) 状态为 design-candidate，仅用于 v8 快照。它使用 id、type、name、entryRef、memberRefs、renderer，将 Implementation 的13个 cli 引用合并为一个工具，以 cli.readme 为入口。这六个字段是验证展示的例子，**不是正式 envelope 必须采用的字段名或完整模型**。

生成器验证候选版本、身份与引用存在、入口属于成员、成员所有权不冲突、Markdown 入口类型，再将展示信息写入快照。其他资源仍含目录/标题 fallback；这些只允许留在明确标记的旧包适配中，不能充当新包语义。发布后的包契约应提供可版本化的解析方式，UI 不长期累积猜测。

当前工具成员归并为同一语义节点，引用成员的外部活动指向工具；同一资源内部载体连接不生成伪自环。保留真实原始引用以支持影响定位，不能误删跨资源真实关系。默认工具说明、实现信息折叠；单脚本直接源内容。README 复用克制编辑能力，不增加命令表单或 IDE。

## 正式适配与验证边界

包与服务需提供可验证的身份闭合、成员/入口定位、类型和内容能力、路径边界、精确引用及完整性状态；渲染不得执行任意 HTML/JS。增删改名和内容修改沿统一校验提交路径，删除检查全部成员外部引用，改名保持身份。缺失/未知用途必须有诊断，不能当零引用或自动归为参考资料。

正式字段、事务与通知接口待 owner 承接；两个 issue 当前是需求输入，不因 v8 可展示就视为契约已发布。
