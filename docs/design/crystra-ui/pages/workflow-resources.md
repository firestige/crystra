# 工作流工作台 · 资源配置

更新：2026-09-13。资源配置以用户可理解的语义资源及关系为中心，替代文件目录和执行配置卡片方案，不展示第二份活动图。后续业务逻辑同时遵循[业务接入需求](workflow-studio-contracts.md)与[包消费边界](resource-envelope.md)。本文是当前需求，样本限制单独说明。

## Workspace 与布局

工作台 Agent 的 workspace 为某个具体 workflow 的包目录，例如 `workflow-package/implementation/`，不是整个项目或全部 workflow 的集合。流程设计、资源配置、结晶分析是该 workspace 的三种投影。

工作台共享左侧 Chat / 右侧展示，分界线可拖拽；左栏最小360px，最大为可使用宽度的50%。键盘左右方向键每次移动16px，Home/End移至边界。切页保留对话草稿、栏宽、文件选择和详情页签。窄于720px保留最小工作宽度。

资源展示区分为资源列表和文件检查区，以低对比 divider 分隔。列表默认260px；展示区不超过760px时200px，不超过520px时160px。检查区占满剩余高度，文件内容与关联图独立滚动。列表本身滚动，检索保持可见，路径只在右侧折叠的存储信息中按需显示。

## 资源内容浏览

- 左侧使用下文定义的语义资源分组与名称列表，搜索名称、用途和包内路径。内部定义由 Agent 管理。
- 点击资源显示名称、类型及“内容 / 关联图”页签。Markdown 预览由 dsh-web 的公开 MarkdownText 组件渲染；代码和纯文本只显示源码编辑器；图片只显示预览。文件超过300,000字符提示截断并禁用编辑，避免保存残缺内容。
- “在对话中讨论此文件”图标带 tooltip，将 workspace 和文件路径加入左侧输入草稿并聚焦，不自动发送。
- role/action-prompt、下载的 skill 及附带文件、template、cli 等按资源类型组织，能力附带文件在右侧访问；页面不另造执行主体配置。节点绑定仍在流程设计中处理。

## 关联图

关联图占满整个检查区，使用 D3 forceSimulation 力导向布局：连边吸引、多体斥力、碰撞避让及弱中心力共同决定位置，不按层级排成流程。初始展示当前语义资源两跳内的双向邻域（含共享资源的连带关系），详情中“展开连带关系”将选中节点两跳邻域加入图中；折叠 Action、Route、资源声明等内部中间层，只显示活动、角色、语义资源、产出及外部资源。关系来自包内明确声明，不按名称推测；Action Prompt 只关联声明的活动。

调用边为蓝色实线，图例明确“调用（配置允许）”；当前仅由活动经允许执行配置到职责的声明推导，不代表运行已发生。引用边为绿色虚线，只表达有明确声明来源的资源依赖及材料/产出关系，详情保留具体语义。Markdown 文档导航链接和“随能力包提供”的成员归属不能自动当作业务依赖；必要时作为独立导航或存储说明。使用颜色和线型双重区分。

选中任意节点，高亮可抵达它的上游路径和从它出发的下游路径，其余节点与边减淡。遍历记录已访问节点，循环不会无限展开。关闭详情解除选择。图支持空白拖动平移、滚轮缩放、适应视图；节点可拖动，拖动时重新激活力模拟，周围节点随力调整，释放后自然稳定。键盘 Enter/Space 可选择节点。节点为按类型着色的圆点，名称位于下方；当前语义资源使用持久双环，临时选择使用单轮廓强化。图内容或容器尺寸改变时重新适应。节点选择保留视角。

详情以右侧悬浮窗覆盖在画布上，不占固定栏宽，也不在下方追加。展示类型、名称及与其他节点的关系；载体位置仅在折叠存储信息中披露，不直接暴露契约 JSON。文件节点可从浮窗打开内容。暂无选择时不显示浮窗；未发现关系时仍显示当前资源，不声称它必定未使用。当前样本不伪造与流程图的活动 ID 跳转；正式接入应通过同一 workspace 稳定节点标识定位活动。

语义变量：`--relation-call` 映射 `--color-status-info-text`；`--relation-reference` 映射 `--color-status-success-text`。节点使用全局背景和类型语义色；浮窗使用全局 Card 背景、减淡边框及阴影，圆角保留。共享 Typography、IconButton、WidgetTooltip 提供文字和操作。浏览器验收：`assets/workflow-resource-graph.test.mjs`。

## 样式与组件资产

SearchField、Tabs、IconButton、Button、Typography 与 WidgetTooltip 复用共享组件。文件行整体 hover/selected；嵌入图标没有独立边框。关联图连接线表达有方向的关系。

资源详情工作面不使用 Card 容器，背景使用 `--color-background-workspace`；文字与 divider 使用 `--color-text-*`、`--color-border-subtle`；交互使用 `--color-interaction-*`。不建立页面专属配色。布局规则位于 `workflow-resource-browser.css`。

帮助通过 help icon 打开居中、有遮罩的模式框；说明引用含义及预览边界，避免说明占据工作区。

## 基础源码编辑（2026-09-12）

实现优先级：dsh 第一方实现 > 成熟开箱即用第三方实现 > 自行实现。当前 dsh 文档服务只读；预览复用 `@deepseek-ai/dsh-client-ui-primitives@0.1.5-rc.2` 的 `MarkdownText`，即侧边文档预览使用的组件；源码编辑采用 CodeMirror 6 官方模块。无富文本、自动补全、语言服务器、终端或调试器。

- 编辑：行号、语法高亮、Tab 缩进、查找替换、撤销重做。工具入口使用中文，Cmd/Ctrl+S 保存。Esc 后 Tab 可移出编辑器。Markdown、JSON、YAML、JS/TS、Shell 使用对应语言支持，未知类型为纯源码。
- 切换预览可以观察未保存草稿的排版，返回编辑保留撤销历史。编辑中的文件继续保留关联图页签；引用关系是快照结果，草稿修改不会伪造重新解析结果。
- 文件详情头部以单行 Row 从左到右排列文件标题、内容/关联图导航、操作按钮；标题区内部显示资源名与资源类型 subtitle；不另设第二行工具栏。导航透明、无卡片背景，以文字状态和底部指示线表达选中。Action group 统一 ghost，包含加入 Chat；保留查找替换、撤销、重做、取消及保存，按当前能力禁用而非隐藏，编辑器内部不重复设置工具栏。长标题省略，极窄宽度横向滚动，维持单行高度。保存/取消位于该行右侧，未保存状态位于 footer。取消恢复已保存内容。切换其他文件时，模式框提供继续编辑、放弃修改、保存并切换；保存失败不切换。
- 保存比较当前内容与开始编辑的基线；有外部修改则拒绝覆盖并保留用户草稿，可展开最新内容进行核对。用户明确确认保留草稿后更新基线，再次保存仍会重复比较；没有强制绕过检查的保存。
- 关闭或刷新页面时对未保存内容触发浏览器离开提醒。工作流样本切换在页面会话内保留编辑草稿。样本保存提示“已保存到页面样本 · 未写入磁盘”。
- 正式集成：保存指向具体 workflow workspace 的草稿文件，通过服务端 expected-version/hash 条件写入完成原子冲突检查；不能将客户端检查替代服务端门禁。已发布版本只读，需进入可编辑草稿。保存后由包索引更新引用关系；版本发布统一校验。HTML 不实现真实写入、发布状态服务或 Agent 并发文件监听。

宿主适配位于 `wsr-ui/packages/bi/preview-host/workbench.tsx`，共享 UI 接收渲染能力，不直接导入 dsh。主题映射资产为 `src/dsh-document-theme.css`：dsh 的文字、背景、链接、边框与代码块 token 映射到 Crystra 语义变量，不复制 Markdown 的布局或解析实现。第三方依赖固定版本并更新 dependency-inventory。

验收增加 `assets/workflow-resource-editor.test.mjs`：真实 dsh 标题渲染、CodeMirror 编辑、预览草稿、未保存切换、保存、取消以及外部变更冲突。来源：[dsh 文档预览](https://github.com/deepseek-ai/deepseek-harness/tree/master/packages/client/ui-sidebar-documentpreview)、[CodeMirror 官方基础配置](https://codemirror.net/examples/basic/)。

资源详情作为右侧平面工作面铺满剩余宽高；无 Card 外观和外围留白。标题栏直接复用全局 `page-header.css` 的 `wb-header wb-page-header studio-header` 与 identity / navigation / context slots：标题采用 page-title、类型采用 description、导航采用共享 Header Tabs、操作采用共享 ghost IconButton 默认尺寸与 Icon 默认尺寸。不再保留本页单独试验的18px导航、4px指示线、等宽导航或放大图标尺寸；后续随全局 Header 同步。

编辑区左右无圆角内缩，编辑器使用工作区背景。标题行与正文、正文与 footer 之间保留贯穿 divider。Footer 固定16px高，显示当前行/列、选区字符数及总行数。双轴原生细滚动条默认低对比，hover / focus-within / active 逐级增强，颜色使用 `--resource-scrollbar-idle/hover/active` 映射全局文字色。

Action group 始终显示对应的带 tooltip 图标按钮（含后续加入的改名入口，不冻结为六个）；编辑器不可见或文件不可编辑时禁用查找、撤销、重做，无修改禁用取消，无修改或冲突未处理禁用保存，撤销与重做根据历史栈状态禁用。

文件操作按对话引用、查找、编辑历史（撤销/重做）、保存修改（取消/保存）四组组织，以组间间距和淡短 divider 区分。操作组靠 Header 底部放置，图标与导航文字下缘对齐。原“已保存”移出 Action group；footer 显示“未保存修改 / 无未保存修改”，仅表示当前页面草稿是否有差异，不暗示磁盘持久化。

### 内容视图

Markdown 内容页默认单栏预览。预览区域右上角提供悬浮 ghost 编辑按钮，带 tooltip 和 aria-expanded；点击“开启编辑”显示左侧源码编辑器，右侧保留等宽实时预览，再次点击“收起编辑”回到单栏预览。收起不丢弃草稿、光标或撤销记录；切换资源时恢复默认预览，未保存修改仍通过现有模式框处理。Action group 不设置固定视图切换按钮。代码及纯文本只有编辑器，图片只有预览，均不显示该悬浮按钮。关联图仍为独立导航页。

Markdown 预览实时呈现当前草稿，两个栏独立滚动，中间使用全局淡色 divider。切换视图或关联图不销毁编辑器，保留草稿、光标与撤销历史；Markdown 在同一文件内切换内容和关联图时保留编辑展开状态。取消恢复已保存内容并清空该编辑会话的历史。截断文本为只读编辑器。图片使用 img 等比容纳，不直接插入 SVG 源码；快照仅内嵌不超过5MB的图片，未携带图片数据时明确显示快照缺失提示。

验证：`assets/workflow-resource-views.test.mjs` 覆盖双栏实时预览、编辑展开收起、代码与图片能力约束。

布局实现参考 [D3 force 官方文档](https://d3js.org/d3-force)。该关系图的力导向规则独立于流程设计活动图，不替换活动图的 ELK 布局。

## 资源列表的语义组织

左栏按“角色（Role） / 技能（Skill） / 脚本／工具 / 模板（Template） / 活动指令 / 参考资料”分组，每条只展示资源名称，不展示用途摘要、路径、图标或数量。内部 definition、schema、validator、conformance、driver 等不作为普通资源条目，也不提供“显示内部定义”开关。真实目录仍是 Agent 工作空间，但不作为浏览入口。

资源名优先采用声明名称（职责从 role 声明取得，能力从 SKILL 元信息取得），其次文档标题，最后文件名回退。名称不是标识，选择以稳定资源 ID 定位，保存通过包契约解析到内容载体与基线，重名资源可在右侧按需展开存储信息区分。搜索匹配名称、用途和资源包内路径。无匹配时显示空态，不清除右侧当前选择。

Skill 以整个能力包为一项；右侧提供包内文件选择器，切换文件沿用未保存保护。用途在右侧内容或详情中呈现，内容与关联图保留原入口。底层元信息缺失时不编造用途；角色责任来自包内声明。目录分类是当前快照适配，正式实现应从包资源索引的类型字段提供语义分组，不把目录名当作长期契约。

资源分类采用 Accordion：默认展开当前资源所属分类，其他分类收起。分类头整行可点击，chevron 表达展开状态，支持 Enter/Space；aria-expanded 与 aria-controls 关联内容区域，收起区域不进入键盘焦点。展开收起使用200ms过渡，尊重减少动态效果偏好。检索变化时自动展开命中分类。

分类头在资源列表滚动容器内 sticky 置顶，背景使用 surface，600字重、底部淡 divider；被下一分类自然顶替，不悬浮到整个页面。子项缩进22px、常规字重，仅显示名称。分类之间保留4px间距，资源列表的搜索框保持在滚动区域之外。

分类以活动可绑定的资源类型为原则：Role 与 Skill 平级，技能不嵌套在角色下；执行方式的互斥和资源可用性由绑定约束处理，不通过目录层级表达。当前列表的类型顺序集中在 resource-catalog.ts 的 resourceGroups；流程设计绑定入口应沿用同一分类原则。本轮仅更新资源列表。

## 资源增删与改名

每个分类头右侧提供独立的添加 ghost icon button，与折叠按钮为同级，不嵌套、不触发展开切换；即使分类为空仍保留添加入口。每个资源 list-item 右侧提供删除 ghost icon button，整体条目 hover/selected 高亮，删除不选中或打开资源。图标均有 tooltip 与无障碍名称。右侧 Action group 增加“重命名资源”入口。

添加打开居中且有遮罩的模式框，分类由入口确定，填写名称与初始内容。名称去除首尾空白，同类型禁止重名；当前样本分配独立稳定路径，不从用户显示名称生成路径。预览对初始 Markdown 的本地引用检查可解析性，失败保留表单和输入，不创建半个资源、不发成功通知。成功后打开新资源，展开其分类并更新关联索引。正式产品按类型提供创建/导入适配，Agent 生成资源可复用同一提交接口；角色、技能、脚本等还须通过对应格式、包声明、selector 与发布校验，不能把空文本创建样本当成完整资源编译器。

删除先展示目标名称、Skill 包的整体删除范围及引用检查结果。检查包括资源别名、活动/职责/配置入边和包内文件的外部引用，包内自引用不构成删除阻塞。存在外部引用时禁用确认删除，展示引用来源；用户先解除或替换绑定，再回来删除。不会自动级联删除活动或默默解绑。正式实现可从影响清单跳到同一 workspace 的准确绑定位置；当前 v8 的流程图与真实包 ID 不统一，因此仅展示影响清单，不伪造跳转。确认时重新读取当前索引检查，防止检查后新增引用。预览还扫描当前 Markdown 内容补充显式相对链接，索引不完整时不能用零命中声称绝对安全。

改名修改显示名，不改变资源 ID、文件路径或引用 selector。模式框检查同类型重名及打开后名称变化；成功更新资源展示信息。文件移动/路径重命名是独立的引用迁移操作，本入口不承担。当前显示名存储在样本元信息；正式由 workflow-package 的名称更新能力承接，不预设字段。

若当前存在编辑草稿，先复用保存/放弃/继续编辑流程，完成后才打开资源管理模式框；取消、检查失败、保存冲突均不产生资源变更事件。删除后选择剩余资源；分类为空仍可添加。

### 引用事务与 Agent 通知

正式提交由 workspace 服务负责：验证草稿可写性、expected revision、名称、类型和引用完整性，在同一事务中修改文件及包索引，并写入事件 outbox。事件包含 eventId、workspace、resourceId、operation、before/after revision、旧/新名称、变更路径及受影响引用。索引更新成功后再发送给当前 workflow Agent。添加不自动绑定资源；删除不自动选择替代品。Agent 据此失效旧缓存、重新读取相关资源，必要时提出受影响的流程调整，不能覆盖用户刚完成的修改。

通知是系统资源事件，不伪造用户话语，也不视为用户批准 Agent 后续修改。事件按 workspace revision 排序、按 eventId 幂等消费，失败进入待重试状态；不回滚已提交资源，也不谎报“LLM 已收到”。UI 区分已提交、通知待发送、已投递与失败可重试。

当前 v8 只修改内存快照。成功操作写入 `window.crystraResourceEvents`，状态为 pending-runtime，并派发 `crystra-resource-changed`；共享 Chat 显示清楚标记的演示通知。没有真实磁盘写入、事务 outbox 或 LLM 调用；刷新恢复快照。浏览器验证覆盖引用阻塞删除、新建、改名、无引用删除与每次成功操作恰好一条演示通知；领域测试覆盖失败不变更/不通知及改名保持引用身份。

关联图中的资源节点名称复用 resourceCatalog，与左侧列表及用户修改后的显示名称一致；Skill 节点展示能力名称，类型由颜色、图例与 tooltip 表达，不以 SKILL.md 命名。缺失名称元信息及有效标题时回退能力包目录名。路径仅在详情展示，长节点名称换行显示，不截成通用文件名。

关联图以正在浏览的资源为锚点：该节点使用双环、上方“当前资源”文字和加重名称，图例明确双环含义；选择其他节点或展开连带关系后仍保留该标识，不随非关联节点减淡。类型颜色仅表示活动/角色等类别，选中高亮仅表示临时检查对象，不改变当前资源身份。

节点类型资产集中在 `src/domain/resource-relation-types.json`。所有节点统一为圆形，仅以 `--relation-type-*` 配色区分活动、角色、技能、脚本/工具、模板、产出、参考资料和活动指令。节点内不显示类型文字，下方保留资源名称，tooltip 提供类型与名称。类型图例常态展开，横向排列并按宽度换行，不需要点击展开。当前资源使用外围双环与文字，选中状态只强化内部圆形轮廓；边的调用/引用颜色及线型语义独立。

关联图名称换行使用 Intl.Segmenter 的词边界，按当前字体实际宽度组成每行（目标144px），不按固定字符数截断。英文单词、不可拆标识符保持完整，超长单词允许超出目标宽度；中文按词分段，闭合标点随前词，显式换行保留。

## 语义资源身份与存储投影

列表与关联图共用 resourceCatalog 的 id、aliases、名称、类型及内容定位。Role 定义、包资源索引和承载内容的文件映射到同一个语义资源；Skill 索引和 SKILL.md 同样归一。归一根据明确声明关系完成，不按名称合并，所以同名但不同身份的资源仍然独立。图上的“当前资源”使用归一后的身份，合并内部边后不生成自引用；活动直接连到语义 Role。能力附属材料仍可按实际依赖出现，但不是额外的能力节点。

右侧标题显示资源名称、副标题显示类型，不默认显示路径或索引 JSON。用途与可编辑内容保留；技能的附属内容通过折叠入口按需访问，入口内容称为能力说明。路径放进“存储信息”披露区，关联图浮窗也遵循该规则。查看附属内容时，关联图仍锚定用户选择的能力。新增、改名、删除继续通过资源服务/预览适配层处理载体与索引一致性，用户不需要以路径操作资源。

当前快照对没有声明 ID 的资源使用载体定位生成临时 ID，仅属于样本适配；正式资源索引应提供独立、持久的 resourceId。

### 资源选择与视图导航正交

“当前资源”和“当前视图（内容/关联图）”是独立状态。左侧选择资源、切换附属内容，以及新增后选择、删除后的后继选择，均只更换数据，不自动修改视图导航。改名、取消编辑也不改变导航。只有用户明确点击导航才切换视图；首次进入默认内容。

切换资源仍执行未保存修改保护，取消切换时资源和视图均保持原状；确认后用新资源更新当前视图。关联图切换资源时重置旧节点选择与展开范围，重新布局并标记新的当前资源，不能残留上一资源的详情。内容视图下 Markdown 恢复默认预览，这属于内容呈现状态，不影响页面导航。

## CLI 工具资源

CLI 按一个工具对象呈现，默认渲染其 README；实现脚本、库和测试不单列资源。实现文件通过右侧折叠“实现信息”查看。工具成员引用归并到工具身份，因此引用某个成员的活动不会连接到重复的源码节点。消费需求及非规范字段例子见[资源 Envelope 消费要求](resource-envelope.md)，当前 Implementation 样本已经应用。


## 包语义缺口与接入验收

工具不是文件数展示：多个文件协同工作的资源统一作为工具，默认说明文档；单文件脚本可直接源码。当前 CLI README 适配只是此规则的样本，不能将规则限制为 CLI。说明文档能力已提交 [#269](https://github.com/firestige/workflow-self-recursive/issues/269)。

目录及资源的用途、消费者、是否适合用户展示，由 workflow-package 明确，见 [#270](https://github.com/firestige/workflow-self-recursive/issues/270)。`agents/routes.md` 属于设计/维护路由资料的已发现例子，不因 Markdown 链接多就被当成业务参考资料。UI 不擅自删除 agents 目录，也不按目录名猜正式语义。没有关系的资源可能是未使用或索引不完整；悬空引用则是目标解析失败，二者分开诊断。

当前快照仍可能通过文件 fallback 暴露 agents/routes.md，并将普通文档链接带入关联图；这是待纠正的适配缺口，不是允许的正式行为。生产必须提供声明来源、关系类别和完整性状态，索引未完成时不得以“零引用”准许删除。

验收编号见[RS-01 至 RS-06](workflow-studio-contracts.md#需求验收与接入缺口)。现有浏览器样本覆盖列表、编辑、视图切换、管理和图交互；不证明真实包写回、绑定 ID 贯通、通知或正式 envelope 已实现。
